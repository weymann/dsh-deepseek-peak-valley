# 003-DSH 集成层 · 测试-验收用例

> 状态: 草稿 | 读者: 测试/验收（其余不读）
> 按 B-03 分层，覆盖接口契约定义的验证点（bundle 契约 / 插件入口 / 挂载位置 / 自动判定 / HMR 与清理）

## 用例 1 · Bundle 契约校验

- 前置: 插件包已构建，存在 `package.json` 与 `cordis.patch.yml`。
- 步骤: 检查 `package.json` 的 `dsh.client`、`exports["./client"]`、`dsh.bundle.patch` 与 `cordis.patch.yml`。
- 期望结果: `dsh.client.platform === "web"`；`exports["./client"]` 指向真实存在的构建产物；`cordis.patch.yml` 为顶层数组且含稳定 `id` / `name` / `config`；bundle patch 与 exports/files 一致。

## 用例 2 · Client 入口加载

- 前置: 插件已安装到 scratch profile 并启动。
- 步骤: 观察 client fiber 激活与 `apply(ctx)` 执行。
- 期望结果: `inject` 依赖满足后 fiber 激活；`apply` 执行挂载；必需 service 未就绪时不抢跑，pending/failed 状态可诊断。

## 用例 3 · 挂载位置

- 前置: 组件在 DSH Web 中加载成功。
- 步骤: 观察侧边栏左下角。
- 期望结果: 组件位于 **左侧边栏 · 左下角 · 设置上方**；组件下方可见齿轮「设置」入口。

## 用例 4 · 双态挂载（展开 / 收起）

- 前置: 组件已挂载。
- 步骤:
  1. 侧边栏展开：观察组件形态；
  2. 收起侧边栏：再次观察。
- 期望结果: 展开态显示完整报价；收起后折叠为紧凑指示器，位置仍在左下角设置上方；两种形态均可见「高峰/空闲」时段信息。

## 用例 5 · 接入后自动判定时段

- 前置: 组件接入 DSH Web，无手动覆盖。
- 步骤: 在不同北京时间（高峰窗口内 / 窗口外）下加载，读取 `body[data-period]`。
- 期望结果: 高峰窗口（09:00–12:00、14:00–18:00）内为 `peak`，其余为 `idle`；与 001 时段规则一致。

## 用例 6 · HMR / 清理

- 前置: 构建 watcher 运行中。
- 步骤:
  1. 修改 client bundle 内容（如某款风格文案），观察 HMR；
  2. 修改 manifest（如 `exports`），观察变化；
  3. 触发 fiber dispose，检查残留。
- 期望结果: client bundle 内容变更走 client HMR（fiber dispose/reload，DOM/样式/事件随之更新）；manifest/exports/profile 变更需重启而非热更；dispose 后 DOM、事件监听、样式注入与 controller 全部清理，无残留。

## 用例 7 · 多会话状态隔离

- 前置: 组件支持 per-session 状态（`DualState` 按会话记忆时）。
- 步骤: 在两个会话中分别展开/收起组件，来回切换。
- 期望结果: 每个会话的展开/收起状态独立、互不串扰；连接重置后仅重同步已读对象。

## 用例 8 · 免责声明常驻

- 前置: 组件在 DSH Web 中可见。
- 步骤: 检查组件说明 / 页脚。
- 期望结果: 常驻「价格基于公开报价仅作演示，正式接入以官方实时接口为准」免责文案。
